# Data classification

The kinds of data a HealthLog instance holds, the protection level each gets,
and what each level requires: encryption, logging, retention, access, browser
storage and backups. What the operator has to supply is said at each point;
the app cannot encrypt a disk it does not own.

Reproductive-health data has its own, more detailed note:
[`cycle-data-threat-model.md`](cycle-data-threat-model.md) and
[`self-hosting/reproductive-health-data.md`](../self-hosting/reproductive-health-data.md).

## Levels

| Level              | Meaning                                                                                                                              | GDPR                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------ |
| **S: Secret**      | A value that lets somebody act as a user or as the instance. Never stored in a form that can be used; never shown again once issued. | n/a                      |
| **H: Health**      | Data concerning health. Everything a user records or imports about their body, mind, medication and care.                            | Special category, Art. 9 |
| **H+: Intimate**   | Health data whose disclosure carries a legal or social risk of its own: reproductive and sexual health, free text, documents.        | Special category, Art. 9 |
| **P: Personal**    | Identifies or describes a person or their devices, without being health data.                                                        | Personal data, Art. 4    |
| **O: Operational** | Instance settings, job state, aggregate metrics with no person in them.                                                              | none                     |

The list of encrypted columns is not hand-kept: `ENCRYPTED_COLUMNS`
(`src/lib/crypto/encrypted-columns.ts`) is checked by
`src/lib/crypto/__tests__/encrypted-column-writers.test.ts`, which follows
every value produced by the encryption helpers into a Prisma write and fails
on a column that receives ciphertext without being registered. The key
rotation walks the same registry.

### Browser storage in detail

The persisted query cache (`src/lib/pwa/query-persister.ts`) keeps only keys
under `dashboard` and `chart-data` and the widget layout, drops the briefing
text, expires after 24 hours and is skipped entirely while a shared record is
open. `clearCachesForSessionEnd` (`src/hooks/use-auth.ts`) clears it, the
in-memory cache and the service worker's page and data caches on sign-out and
on any 401. The service worker never caches `/api/*` and keeps a page only
when the server marked it anonymous (`public/sw.js`). Two small items survive a
sign-out today: the recently used mood tags and a running seizure timer in
`localStorage`.

### Backups and dumps

| Copy                                          | Health data inside                                        | Operator's part                                                                                                                                                                                                                  |
| --------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nightly and pre-migration database dumps      | H in plaintext, H+ and S as ciphertext                    | They sit beside the database volume in the same trust zone. Encrypt that volume, keep the host's access as tight as the database's, and keep the copies off the host ([`ops/disaster-recovery.md`](../ops/disaster-recovery.md)) |
| Off-host dump and per-account objects         | sealed with `BACKUP_ENCRYPTION_KEY`                       | A bucket lifecycle rule; the key held outside the server                                                                                                                                                                         |
| In-database per-account copies (`DataBackup`) | sealed with the data key                                  | none                                                                                                                                                                                                                             |
| A user's export                               | plaintext JSON or PDF, or the passphrase archive (`HLX1`) | none; the user chooses                                                                                                                                                                                                           |

## What the operator must do

- Encrypt the disk or volume that holds the Postgres data directory and the
  `backups` volume. Health values (level H) are plaintext in the database, and
  column encryption covers only H+ and S.
- Keep `ENCRYPTION_KEYS` and `BACKUP_ENCRYPTION_KEY` somewhere other than the
  database host's disk where the deployment allows it
  ([`self-hosting/secrets.md`](../self-hosting/secrets.md)).
- Restrict who can read the container's logs and ship them to a system with
  its own retention ([logging](logging.md#shipping-logs-off-the-host)).
- Do not put a caching proxy in front of the app that ignores
  `Cache-Control: private`.
