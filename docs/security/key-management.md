# Key management and cryptographic inventory

Every key and secret a HealthLog instance holds, who makes it, where it lives,
how it is replaced and what a replacement breaks; then the algorithms in use
and which data each key may protect. The step-by-step runbooks stay where they
are and are linked, not repeated:

- data keys: [`ops/encryption-key-rotation.md`](../ops/encryption-key-rotation.md)
- off-host backup key: [`ops/backup-restore.md`](../ops/backup-restore.md#off-host-copies)
- what a restore needs: [`ops/disaster-recovery.md`](../ops/disaster-recovery.md#the-keys-a-restore-needs)
- the recovery kit (which keys an operator must hold outside the server):
  [`self-hosting/getting-started.md`](../self-hosting/getting-started.md#save-the-recovery-kit)
- passing secrets as files (`<NAME>_FILE`, Docker secrets):
  [`self-hosting/secrets.md`](../self-hosting/secrets.md)

## Principles

- **The operator generates and holds the instance keys.** No key the app
  encrypts with is stored in the database. Keys reach the container as
  environment variables or, from 1.50.0, as files named by `<NAME>_FILE`; the
  entrypoint resolves the file form before anything else starts and refuses to
  start when both forms are set with different values or the file is empty or
  unreadable.
- **Fail closed.** A missing, short or malformed key stops the process instead
  of writing plaintext or keying a hash off weak material:
  `src/lib/crypto.ts` (data keys must be 64 hex characters or 32 bytes of
  base64 outside development), `src/lib/auth/hmac.ts` (`API_TOKEN_HMAC_KEY` at
  least 32 characters), `docker-entrypoint.sh` (refuses to start without
  `DATABASE_URL` and `API_TOKEN_HMAC_KEY`). A boot canary
  (`src/lib/crypto/canary.ts`) refuses a data key that does not open the
  database it is pointed at.
- **Keys are shown by fingerprint, never by value.** Admin, Encryption, the
  backup manifests and the recovery kit show the first 12 hex characters of
  SHA-256 over a random key, and an scrypt-based fingerprint for a key the
  operator chose as text (`src/lib/database-backup/dump-core.mjs`,
  `fingerprintSecretText`), so a guessed phrase cannot be checked offline.
- **Third-party credentials entered in the app are data.** Integration client
  secrets, OAuth access and refresh tokens, AI provider keys, Nightscout and
  Dawarich tokens and the push-relay key pairs are stored as ciphertext under
  the data keys (the `*Encrypted` columns, registry in
  `src/lib/crypto/encrypted-columns.ts`). They are rotated at the provider and
  revoked by disconnecting the integration.

### Which process needs which secret

With a web/worker split ([`self-hosting/scaling.md`](../self-hosting/scaling.md)),
give each container only what it uses. Both processes run the entrypoint, which
needs the owner `DATABASE_URL` at start and removes it before the app runs.

| Secret                                                                              | Web                                                                    | Worker                                      |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| `DATABASE_URL` (owner, for the entrypoint), `ENCRYPTION_KEYS`, `API_TOKEN_HMAC_KEY` | yes                                                                    | yes                                         |
| `OIDC_CLIENT_SECRET`, `SETUP_TOKEN`                                                 | yes                                                                    | no                                          |
| Webhook secrets (Withings, WHOOP, Telegram, deploy)                                 | yes                                                                    | no                                          |
| Integration client secrets (Polar, Oura, Strava)                                    | yes (connect callback)                                                 | yes (token refresh during sync)             |
| `VAPID_*`, `APNS_*`, `SMTP_*`                                                       | yes (test sends, sign-in alerts)                                       | yes (reminders and every scheduled message) |
| `BACKUP_ENCRYPTION_KEY`, `BACKUP_ENCRYPTION_PREVIOUS_KEYS`, `BACKUP_S3_*`           | only for the admin connection test and the recovery kit's fingerprints | yes (off-host copies, restore drill)        |
| `WALLET_APPLE_*`                                                                    | yes (pass build and pass web service)                                  | yes (pass update pushes)                    |
| `LOKI_*`                                                                            | if the web process ships its own events                                | if the worker ships its own events          |

The `BACKUP_*` row is the one an operator can narrow: leaving the backup key
off the web container costs the admin connection test and the key's line in
the recovery kit, and nothing else.

## Compromise response

| Exposed                                               | Do                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A data key                                            | Add a new key id, rotate every row to it, then drop the exposed id. Treat every database dump and in-database copy written before the rotation as readable by whoever holds the key, and delete the ones you do not need.                                                  |
| `API_TOKEN_HMAC_KEY`                                  | Replace it and restart every container at once. The consequences above are the remedy: every credential the key protected is void. Tell the users to sign in again and to re-create API tokens, share links and feed subscriptions.                                        |
| `BACKUP_ENCRYPTION_KEY`                               | Set a new key. The exposed one opens every object in the bucket sealed under it; delete those objects once a fresh nightly copy exists, instead of listing the key as previous.                                                                                            |
| A database dump or volume                             | Encrypted columns stay sealed while the data keys were not stored with it. Everything else in it is readable ([data classification](data-classification.md)). Rotate `API_TOKEN_HMAC_KEY` too if the dump could be combined with it, since it holds the credential hashes. |
| One account's credentials                             | [`ops/security-recovery.md`](../ops/security-recovery.md): a password reset revokes every session, token, trusted device and step-up elevation of that account.                                                                                                            |
| A provider secret, webhook secret, APNs or wallet key | Rotate it at the provider as in the table, then set and restart.                                                                                                                                                                                                           |
| The push relay sender key                             | `POST /api/admin/push-relay/rotate-sender-key`.                                                                                                                                                                                                                            |

Record what was rotated and when outside the instance; the app's audit log
records the admin-driven rotations (data keys, sender key) but not changes to
the environment.

### A note on agility

The data keys and both backup envelopes carry a key id, so they rotate without
downtime. `API_TOKEN_HMAC_KEY` does not: its hashes and signatures carry no key
id and there is no verify-only previous key, so replacing it voids every
credential at once. That is acceptable for the response to a leak, which wants
exactly that, and is the reason it should not be rotated on a schedule.

### Which data each key may protect

| Key                     | May protect                                                                                                              | Must never protect                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `ENCRYPTION_KEYS`       | Data at rest in the database: health text, documents, third-party credentials, account copies, short-lived state cookies | Off-host copies (they take the backup key so one leak does not open both); credential hashes |
| `BACKUP_ENCRYPTION_KEY` | Objects written to the off-host bucket                                                                                   | Anything in the database                                                                     |
| `API_TOKEN_HMAC_KEY`    | Hashes and signatures of credentials and short-lived signed artifacts; the derived role password                         | Encryption of data: it is not an encryption key and nothing is encrypted with it             |
| Push relay keys         | Push envelopes and relay requests                                                                                        | Anything stored                                                                              |
